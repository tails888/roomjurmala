# ROOM Jūrmala Blender model

The editable source is `room-jurmala.blend`. The website loads `../assets/tour/room-jurmala.glb` only after the visitor opens the tour. The GLB is exported by Blender 5.2 LTS, with embedded material maps and Meshopt mesh compression. It does not need Blender installed on the visitor's device.

## Reconstruction and limits

Reviewed all 21 real venue photographs in `assets/images/gallery` and all 12 MP4s in `assets/videos`. Video contact sheets sampled each second across each clip, including the duplicate optimized hero tour. The material ledger below records the visible corners and details. Website illustrations, logos and service sketches were excluded as architectural evidence. Poster frames duplicate the reviewed videos.

This is a manually reconstructed, simplified model, not a laser scan or a measured digital twin. No measured floor plan was supplied. The envelope is approximately 10 × 9.6 m and 3.05 m high. Scale, window spacing, clearances and minor objects are inferred from furniture and architectural cues. These numbers must not be used for booking capacity, construction or accessibility measurements.

The representative furnishing arrangement follows the empty-room June tour. Yoga mats, temporary seminar furniture, Christmas decorations and other mutually exclusive event arrangements are not all combined into the same floor plan. Closed service doors are represented, but unphotographed interiors are not invented or accessible.

## What is in the model

Separate named Blender collections contain architecture, pleated curtains/windows, entrance furnishings, storage/toys, soft play, table football, kitchen appliances, tables/chairs, wall details, light fittings, lights and four cameras. Bevels remain editable in the `.blend`. All image dependencies are packed.

The brick map is the existing illustrative website texture, not a scan of the venue wall. Oak, carpet and vinyl maps are deterministic procedural approximations generated by `make_materials.py`. Small landscapes, toys and appliance controls are simplified. People and private information on notice boards are not reproduced.

## Rebuild

Run `python3 blender/make_materials.py` with Pillow and NumPy installed. Then run `blender --background --factory-startup --python blender/build_room.py -- --renders` from any directory. Omit `--renders` for a faster source/GLB export.

Outputs are the packed `.blend`, GLB, collision layout JSON and four camera previews. The browser coordinate system is X across the room, Y up and Z toward the front white/sage wall. `P()` converts this to Blender's Z-up coordinates. Collision rectangles are written from the same object-placement source as the visible furniture. The service block is deliberately closed.

## Website integration

`tour-world.js` loads the GLB with locally vendored Three.js GLTFLoader and MeshoptDecoder. It owns model loading, texture cleanup and lighting. `tour-runtime.js` keeps the existing keyboard, mouse, touch joystick, photo reference and zone controls. Loading can be cancelled by closing the tour. Failed downloads or unsupported WebGL expose retry and real-photo options.

The `.blend`, build scripts and camera previews are authoring deliverables. Only the GLB and collision JSON are needed at runtime; the embedded textures do not trigger separate image requests. Changes belong to the GitHub `updates` branch.
